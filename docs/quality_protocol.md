# 后续质量评测与验收协议

本协议是待执行方案，不是已完成的质量评分。

## 数据与版本

先扩充至少200条脱敏请求，按任务类型分层，保留开发集与冻结留出集。每条记录query_id、难度标签、任务类型、标注者、分歧与裁定。记录模型ID、推理框架、采样温度、输出上限、硬件、代码commit及价格参数快照，避免规则修补后又用同一例证明泛化。

## 三策略受控对照

全本地、全云端、混合使用相同提示词与输出长度限制，交错顺序并重复至少3轮。固定提示词不消除随机波动，应同时保存每轮答案、状态、分项token和耗时。全云端若发生降级，该批不能作为纯云端质量/成本基线。新脚本跳过强制基线的分类调用并复用同一agent函数，减少实现差异。

## 评分与盲评

两位评阅者匿名看到答案，不看到模型/策略；按事实正确性、指令遵循、完整性各0至4分评分。预设加权分为0.5×事实+0.3×遵循+0.2×完整性。关键事实错误单独登记，不能被篇幅和语气抵消。代码题尽量用可执行用例，数学题检查关键推导，开放题保留评阅理由与分歧。LLM裁判只作辅助线索，由人工抽检，不以生成模型自评充当地面真值。

## 报告指标

报告路由准确率及Wilson区间；报告端到端延迟中位数、P95与重复轮次；报告独立全云端费用比和同token牌价比，分别标注分母；报告答案加权质量、关键错误率、升级尝试/成功/失败、可用率及降级率。质量等价必须用预先确定的容忍差与置信区间判定，不以路由准确率代替。
