+## 这是什么

本项目面向中小规模人工智能应用，研究简单请求交给本地小模型、复杂请求交给云端大模型时，调用成本、响应延迟和质量风险如何变化。当前实现是可运行的单轮文本工作流，主要价值在于端点适配、显式路由、升级处置、逐请求记录以及可复算的对照实验。它没有多轮记忆、工具执行、检索增强或自主科研能力，不应把名称中的 Agent 理解为完整自治系统。

服务包含四层：Web 页面与 FastAPI 接收请求，规则和模型分类决定难度，本地与云端提供推理能力，SQLite 保存用量和费用。模块分别位于 app、deploy、eval、tools 和 web，路由、客户端、记账相互分离，便于在不重写上层流程的情况下更换推理服务。架构文本原文件见 docs/architecture.txt，正式报告图 1 使用同样的结构。

规则优先处理寒暄、短句、代码和推理关键词，规则未决时调用本地模型做 JSON 分类，分类失败则按文本长度兜底。模型分类并不免费，返回的输入输出 token 应纳入路由成本。本地回答过短或含不确定表述时升级云端；这种自检只检查表面信号，不能承诺回答正确。原始 GPU 记录已经出现 vLLM 名称展开错误和线程池替代进程池的例子。

## 怎么装

普通离线演示需要 Python 3.10 或以上。历史真实 GPU 环境为 Python 3.12.3、torch 2.9.1+rocm7.13.0、transformers 4.57.6。requirements.txt 是 Web 演示依赖，未列入与硬件强相关的 ROCm torch；它使用版本下限而非完整锁文件，不能保证多年后自动得到完全相同的环境。真实 GPU 复现应先确认平台镜像与 torch 是否兼容，再安装其余依赖，不要直接覆盖平台预装 torch。

Windows PowerShell，从项目根目录开始：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
$env:MOCK_MODE='1'
$env:DB_PATH='runs_demo.db'
.\.venv\Scripts\python.exe -m uvicorn app.server:app --host 127.0.0.1 --port 8080
```

Linux 或 AUP 容器：

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
MOCK_MODE=1 DB_PATH=runs_demo.db python -m uvicorn app.server:app --host 127.0.0.1 --port 8080
```

浏览器打开 http://127.0.0.1:8080。设置 MOCK_MODE=1 后无需 GPU 与有效云端密钥，返回文本会包含 mock 标记。此模式只验证页面、接口和记账，不产生真实模型的性能结论。首次安装的耗时与网络有关，当前没有陌生外部使用者的三十分钟运行记录，不能把开发者环境的成功当作该验收已完成。

## 怎么跑

演示一，输入“你好”，预期规则判为 easy，页面显示本地分支及本次估算费用。演示二，输入“用 Python 写一个带超时的进程池”，预期强特征命中 hard，进入云端分支。离线模式仍返回带 mock 标记的模拟内容。演示三，输入“帮我 review 这段 SQL：select * from orders where created_at > '2024-01-01' and status = 1”，观察路由解释，并对照历史失败样例；真实模型重新运行可能给出不同分类，不应强行要求重现完全相同的一次答案。

接口测试示例：

```powershell
$body = @{query='你好'} | ConvertTo-Json
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8080/api/chat -ContentType 'application/json; charset=utf-8' -Body ([Text.Encoding]::UTF8.GetBytes($body))
Invoke-RestMethod http://127.0.0.1:8080/api/stats
Invoke-RestMethod http://127.0.0.1:8080/healthz
```

主服务对外端点是 /api/chat，而不是模型服务的 /v1/chat/completions。请求可附 force_route='easy' 或 'hard' 用于演示强制分支，但这不是关闭路由器的严格消融：当前代码仍会先计算一次路由，再覆盖难度。返回结果包括 answer、route、reason、decided_by、model、latency_ms、token 用量、cost_cny、baseline_cost_cny、escalated 与 degraded。

真实 GPU 服务需要在独立终端启动，先确认 torch.cuda.is_available() 为真，再加载完整模型目录：

```bash
python deploy/local_server.py --model /home/jovyan/models/qwen2.5-1.5b --host 127.0.0.1 --port 8000
```

完整目录需有配置、tokenizer 及权重文件，不能只下载单个 model.safetensors 就声称具备完整模型。配置 .env 中 LOCAL_MODEL 与服务返回名称一致，LOCAL_BASE_URL 指向 http://127.0.0.1:8000/v1，MOCK_MODE=0，并填入自己有权使用的 CLOUD_API_KEY。密钥只写本地环境文件，不提交仓库、不放入报告截图。source zip 已排除原 .env、虚拟环境和数据库。

在另一个项目终端依次执行：

```bash
python tools/preflight_stdlib.py
python eval/run_eval_stdlib.py
python tools/capacity_plan.py --gpu-tps 32.6
```

预检须确认配置、GPU、本地与云端均符合预期。若云端不可用，可用 --skip-cloud 诊断本地链路，但不得将其输出称为真实全云端基线。标准库评测脚本直接发 HTTP 请求，不经过 app/agent.py；因此该脚本不因 MOCK_MODE=1 自动获得离线 HTTP 模型服务，也不会把每次评测写入 Web 的 SQLite。真实评测前确认请求去向，不要把“零依赖”理解为不需要服务器、权重或网络。

## 效果如何

最终历史测试集共二十四条，其中简单十三条、复杂十一条。三策略各运行一次，截图显示全本地平均延迟 2858 毫秒、估算费用 0.0151 元；全云端 2067 毫秒、0.0829 元；混合 2165 毫秒、0.071379 元。混合费用由最终 CSV 逐行加总，与独立全云端相比约下降百分之十三点九。按 CSV 自身“同 token 云端牌价”计算的下降约百分之十四点五，两者不是同一个分母，不能互相替代。

混合路由准确二十三条，规则判定十七条，三个请求发生本地到云端升级。纯本地、纯云端、升级支路分别十一、十、三条，费用分别为 0.004088、0.064907 和 0.002384 元。混合延迟中位数为 1850 毫秒，最近秩 P95 为 4513 毫秒。样本量小且没有重复测量，这些数字只能描述该次实验，不构成生产 SLA 或同等质量保证。路由准确率的 Wilson 百分之九十五区间约为百分之七十九点八到九十九点三。

独立 GPU 前向实验为八条请求、greedy 解码、输出上限九十六 token，报告峰值显存 2.99 GB。逐请求输出速率的均值为 32.6 token/s，总输出除总时间约 29.6 token/s，两种聚合方式必须区分。该吞吐不是输入输出总 token 吞吐，不能直接用于每请求九百总 token 的精确生产预算。首条含预热，七条后续数据也不能当作独立的硬件优化前后试验。

可核验材料位于 docs/evidence/final：result_stdlib.csv 是最终混合逐条明细，recomputed_metrics.json 是本次复算结果，aup_gpu_run.md 包含原始回答，07-eval-real-3.png 是三策略汇总。初轮云端全失败的结果只用于故障过程说明。现有 CSV 没有全部策略答案，不能凭它做关规则或关升级的完整消融；新消融必须重新执行并保留答案与调用明细。

## 已知问题

第一，质量自检依赖长度与关键词，自信的错误可能漏检，正确短答可能误升级。当前未有人类答案盲评，因此不能把成本下降描述为质量无损。第二，SQL 专业请求存在漏判，应补充规则并对训练外留出集验证，避免只修复测试集中的一条样例。第三，修订版已保留分类格式失败的已知用量，但提供方超时后若未返回usage，客户端无法获知其是否计费，仍需与供应商账单核对。

第四，修订版已区分升级尝试、成功与失败，并持久化degraded及分项用量；这些修复通过确定性故障回归，修订版真实GPU语义质量仍需重测。第五，本地 HTTP 服务持有全局生成锁，多请求会排队，不能把并发连接数当作同时生成数。第六，当前输出不是完整的流式协议实现，鉴权、限流、日志脱敏、持久化迁移均未达到生产要求。第七，页面包含清空记录入口，验证时使用独立演示数据库，不对有价值的历史记录操作。

第八，旧capacity_plan.py保留作历史追溯；新增capacity_plan_service.py按活跃窗口、服务时间、分类开销、升级比例和冗余计算。服务时间必须以目标环境实测替换，当前0.5/1/3秒情景不作为采购依据。第九，安装依赖下限没有锁定，完整复现应保存 pip freeze、GPU 环境、模型版本与采样参数。第十，外部验证与三分钟演示视频尚需作者完成，AI 检查不能代替独立使用者。

### 数据记录与故障定位细则

执行一次真实评测后，先查看终端末尾是否出现云端失败告警，再核对逐条记录的模型列；不能只看到费用非零便认为请求已到达指定模型。若云端失败后回落本地，最终模型名称和失败状态必须共同解释。当前最终归档中，模型列可分成纯本地、直接云端和本地到云端升级三类；使用者可按这些类别分组加总费用，但不能从混合策略的答案长度推出全云端的答案质量。

本地服务启动失败时，先判断是权重目录缺文件、显存不足、框架版本不兼容还是端口被占用。下载库报错不代表整个网络不可用；应分别检查域名访问、下载来源、文件完整性与模型加载。若平台没有可用的专用推理引擎，优先保留兼容协议，用已验证的实现完成最小链路，再比较迁移成本。不要为了套用部署教程而反复覆盖平台依赖，导致原本可用的计算环境失效。

成本字段是分析参数驱动的估计值。实际采购还需纳入机器租赁、空闲时间、冗余、网络、存储与人工维护，不能把每千词元单价当作完整的自建总成本。云端价格变化时应保留旧参数快照和计算日期，再创建新的情景结果；不能修改历史实验的价格后继续称其为当时的实测费用。若供应商不返回真实用量，应明确记录缺失，不能把零用量误读为免费调用。

外部验证的目的，是让没有开发背景信息的人按公开说明得到一致的功能结果。验证者应从安装开始计时，记录命令、错误、修复和最终输出，至少检查页面输入、复杂请求分支与统计更新。遇到问题不应直接由开发者接管并宣称首次验证通过，而应保留失败步骤、修订说明并安排复测。验证记录可匿名，但应说明其是否参与开发，并保存可追溯的日期、环境和仓库版本。
